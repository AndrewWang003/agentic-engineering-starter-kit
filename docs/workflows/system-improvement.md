# System Improvement Workflow

## Purpose

System improvement turns reusable lessons from project work into reviewed updates to the central method library.

## Input

- Task retrospective.
- Central feedback file.
- Evidence from the project task.
- Current central system version.

## Output

- System improvement proposal.
- Optional evaluation case.
- Approved updates to docs, templates, skills, or scripts.
- Changelog and version update when released.

## Workflow

1. Read the feedback and supporting evidence.
2. Decide whether the issue is reusable beyond one project.
3. Draft a system improvement proposal.
4. Add or update evaluation coverage where practical.
5. Modify central docs, templates, skills, or scripts.
6. Verify internal consistency.
7. Request user approval for material behavior changes.
8. Update changelog and version.

## Stopping Condition

The improvement is complete when the proposal is resolved, evidence is recorded, affected artifacts are updated, validation is complete, and the release state is clear.

## Approval Boundary

Codex must not directly convert feedback into stable rules without review. Material changes to autonomy, approval boundaries, templates, or skill behavior require user approval.

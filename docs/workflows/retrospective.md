# Retrospective Workflow

## Purpose

Retrospective captures lessons after verification and decides whether any lesson should feed back into the central system.

## Input

- Task contract.
- Verification report.
- Implementation notes.
- Known blockers or deviations.

## Output

- Task retrospective.
- Optional central system feedback or system improvement proposal.

## Workflow

1. Summarize the task outcome.
2. Record what worked.
3. Record what did not work.
4. Classify issues as current-task, current-project, testing, documentation, reusable workflow, or central-system issues.
5. Generate central feedback only for reusable workflow or central-system issues.

## Stopping Condition

Stop when lessons are classified and any central feedback need is clearly marked.

## Approval Boundary

Do not modify central system rules directly from a retrospective. Use the system improvement workflow for reusable changes.

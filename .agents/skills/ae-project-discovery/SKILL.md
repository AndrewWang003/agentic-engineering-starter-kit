# ae-project-discovery

Use this skill when a user wants to explore or initialize a new software project but has not yet approved a project contract.

## Goal

Gather enough information to initialize a project without asking questions indefinitely.

## Procedure

1. Restate the project idea in one paragraph.
2. Identify what is already known.
3. Ask only blocking questions.
4. Classify information as `Confirmed`, `Assumed`, `Open`, or `Deferred`.
5. Apply the discovery stopping rule.
6. Produce a discovery summary and recommendation.

## Required Topics

- Problem statement
- Target user or operator
- Core value
- First delivery scope
- Core inputs and outputs
- Hard constraints
- Success criteria
- Non-goals

## Stopping Rule

Stop when the problem, target user, first delivery scope, core inputs and outputs, constraints, non-goals, and success direction are sufficiently clear, and remaining unknowns do not block initialization.

## Output

Produce:

- discovery summary;
- assumptions;
- open questions;
- deferred decisions;
- readiness recommendation for project contract creation.

## Approval Boundary

Do not create or bootstrap a project until the user approves the discovery summary.
